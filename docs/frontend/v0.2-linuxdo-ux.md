# v0.2 Linux.do 登录与反馈 UX 设计规范

> Status: **Frontend Documentation Repair Complete / Implementation Pending**

---

## 1. 交互与界面规范

### 1.1 Linux.do 登录入口规范 (`/login`)
- **入口位置**: 位于 `/login` 独立页面单页卡片底部，通过 `───── 社区快捷通道 ─────` 分割线隔离。
- **按钮样式**: 全宽高亮大按钮 `[ 🐧 使用 Linux.do 账号登录 ]`。
- **免邀请码标注**: 显眼提示：“💡 L1 级及以上活跃用户可免邀请码直接注册”。
- **常驻特性**: 无论处于 `[邮箱登录]` 还是 `[邀请码注册]` Tab，Linux.do 按钮均常驻可见。

### 1.2 Linux.do OAuth 流程与 Callback 安全规范
- **路由白名单扩展**: v0.2 公开白名单路由扩展为 `/login`、`/` 与 `/auth/callback`。
- **发起授权 (Start)**: 用户点击 Linux.do 按钮 ➔ 重定向至 BFF `/api/auth/oauth/linux-do/start?return_to=<encoded_path>`。
- **BFF 服务端隔离与 303 回调 (Server-side Exchange)**:
  - Linux.do 官方授权后**仅回调 BFF 接口**，绝不直接回调前端 `travel-web`。
  - 前端 JavaScript **绝对不能**接收、处理或交换授权 Code、OAuth State、Access Token、Client Secret 或原始用户 Profile。
  - BFF 服务端完成 Code 换 Token 与 L1 门槛校验后，以 `303` 重定向至前端 `/auth/callback?mode=...&returnTo=...` 或带稳定错误码。
- **回调 Landing 页面 (`/auth/callback`) 交互**:
  - 页面居中展示 Spinner 加载动画：“正在完成身份验证...”。
  - 成功时：前端调用 `GET /api/me` 重新初始化并恢复登录态，随后自动重定向恢复至 `returnTo` 目标路径（登录默认 `/`，显式绑定默认 `/profile`）。
- **失败分类优雅降级 (Error Fallback)**:
  - **`OAUTH_STATE_INVALID` (400)**: 认证流程 State 参数非法或超时（属于 400 类客户端/认证流程错误，非 502）。提示“授权超时，请重试”，提供 `[ 重新登录 ]` 按钮。
  - **`OAUTH_ACCOUNT_INELIGIBLE` (403)**: Linux.do 账号未达到 L1 等级或被禁言。提示：“⚠️ 未达到注册门槛：Linux.do 免邀请码通道需账号达到 L1 等级且无禁言。您可使用 [邀请码 + 邮箱验证码] 注册”，提供 `[ 返回登录页 ]` 按钮。
  - **`IDENTITY_ALREADY_LINKED` (409)**: 该 Linux.do 身份已绑定至其他云途账号。提示：“⚠️ 该 Linux.do 账号已绑定至其他邮箱”，提供 `[ 返回登录页 ]` 按钮。
  - **`OAUTH_PROVIDER_ERROR` (502/503)**: 第三方服务提供商响应异常。提示：“Linux.do 服务暂不可用，请稍后重试”。

### 1.3 独立 `/profile` 个人设置页与身份展示
- **独立路由**: 明确采用独立 `/profile` 路由（受路由守卫保护）。
- **身份与头像展示**:
  - **账号信息**: 展示脱敏邮箱（如 `u***@example.com`）与当前公测额度 (`N/3`)。
  - **Linux.do 绑定状态 (`GET /api/me/identities`)**:
    - 调 `GET /api/me/identities` 仅展示 BFF 下发的最小抽象状态（如 `Linux.do: 已关联`），**不展示不可变 Linux.do ID，不展示原始 Provider Subject**。
  - **头像策略**: 暂不承诺 Linux.do 头像回显。BFF 当前仅返回最小身份绑定状态，不得为了头像将原始 Provider Profile 或 Subject 暴露给前端。前端统一展示预设的品牌手账头像。
- **主动绑定流程**:
  - 登录态下在 `/profile` 点击 `[ 关联 Linux.do 账号 ]` ➔ 请求 `/api/me/identities/linux-do/link/start` ➔ 引导授权 ➔ 成功后 303 跳回 `/auth/callback` ➔ 调用 `GET /api/me` 恢复并返回 `/profile`。
  - 若触发 `409 IDENTITY_ALREADY_LINKED`，弹 Toast 警示：“该 Linux.do 账号已被其他云途账号关联”，绝对不自动合并账号。

### 1.4 行程质量反馈规范 (“有帮助 / 没帮助”)
- **展示位置**: 挂载于结果页 (`/result/:resultId`) 与 详情页 (`/plan/:resultId/:planId`) 底部手写签名下方。
- **“👍 有帮助”**: 点击提交 `POST /api/trip/results/{id}/feedback` (`helpful: true, reasons: []`)。
- **“👎 没帮助”**: 点击后内联展开结构化原因芯片，必须选择一个或多个标准代码（`ROUTE_INEFFICIENT`, `PACE_MISMATCH`, `TRANSIT_INACCURATE`, `PREFERENCE_MISSED`, `OTHER`），点击 `[ 提交反馈 ]` 提交。

### 1.5 城市边界控制规范 (MultiCitySelect 实境对齐)
- **前端受控选择**: `MultiCitySelect.tsx` 为受控点选组件，严格受限于 `SUPPORTED_CITIES` 10 城列表。
- **BFF 后端兜底 (`CITY_NOT_SUPPORTED` 422)**: 若触发 422 错误，不扣减额度，弹 Toast 提示：“当前暂未开放该城市的路线规划”，引导用户重新选择热门城市。

## 2. 决策记录 (Accepted Decisions)

| # | 拷打主题 | 冻结决策 | 核心理由 |
|---|---|---|---|
| 12 | Linux.do 入口 | `/login` 底部分割线大按钮 + L1 免邀请码特别标注 | 社区专属通道醒目，极其利于 Linux.do 社区流量转化；新老用户统一入口。 |

| 14 | 个人设置与绑定 | 独立 `/profile` 路由 + 最小身份展示 + 不暴露 ID/头像 | 明确独立 `/profile` 路由；仅回显最小绑定状态；不展示不可变 ID，不为了头像泄漏 Provider 原始身份。 |
| 15 | 结果质量反馈 | 页面底部轻量挂载 + “👎 没帮助”结构化原因代码提交 | 严格对齐 BFF 契约 `helpful`/`reasons` 代码，为后端模型调优提供标准化归因数据。 |
| 16 | 城市边界控制 | 贴合 `MultiCitySelect.tsx` 点选限制 + BFF `CITY_NOT_SUPPORTED` 兜底 | 完全基于代码实境，`MultiCitySelect` 前端死锁 10 城；BFF 422 兜底防额度浪费。 |
