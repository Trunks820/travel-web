## 2. 变更内容与修复清单 (Implementation & Fix Summary)

### 2.1 按场景计算状态 (Scenario-based Cost Status Mapping)
- 避免使用顶层 `completeness` 决定场景文案。提取共享纯函数 `getScenarioCostStatus` (`src/types/cost.ts`)：
  - 依据 `activeScenario.total_scope` 计算：
    - `full_trip` -> `complete` -> 展示 `"预估 ¥min–¥max"`。
    - `estimated_subset` -> `partial` -> 展示 `"已估 ¥min–¥max"` 并附加 `"部分费用待确认"` 徽标。
    - `unavailable` -> 展示 `"费用暂不可估算"`（绝对不展示任何金额范围）。
  - 双场景未选中时展示 `"选择交通方式查看预估"`（无金额）。

### 2.2 Schema 2.0 TypeScript 严格契约与标签 Mapping
- `src/types/cost.ts`：
  - `CostPriceBasis`: `"sourced" | "reference" | "mixed" | "policy_zero" | null`
  - `CostScenarioId`: `"train_round_trip" | "flight_round_trip" | "without_intercity"`
  - `snapshot_version`: 窄化字面量 `"1"`
  - `CostAssumptionCode` & `CostExclusionCode` 字面量按 `hermes_models.py` 窄化。
- `src/types/trip.ts`：
  - `TripPlan.cost_estimate` 调整为必需字段 (`cost_estimate: CostEstimateSummary`)。
- 价格依据前端渲染映射：
  - `sourced` -> `"来源查价"`
  - `reference` -> `"参考估算"`
  - `mixed` -> `"来源与参考混合"`
  - `policy_zero` -> `"按规则计为 ¥0"`

### 2.3 重复 DOM Anchor ID 清理 (Duplicate Anchor Cleanup)
- 从 `CostEstimateCard.tsx` 根节点移除 `id="cost-estimate"`。
- `#cost-estimate` Anchor 仅由外层 `<section id="cost-estimate">` 附录区容器持有，确保全页 Anchor 唯一。

### 2.4 清理旧版 Budget / Must-Go 遗留与交互修复
- 在 `PlanDetailDemoLight.tsx` 中清理旧版 `budget` / `must-include` scroll spy，`BUDGET` / `MUST-GO` 按钮及对应跳转，替换为单一 `COST` ("出行费用") 入口指向 `#cost-estimate`。
- 为 `PlanDetailClassicPage` 及 `PlanDetailDemoLight` 透传 `activeScenarioId` 与 `onScenarioSelect` 状态，确保场景单选 Radio 可交互。
- 产物包与源码违规字眼扫描确认（`mockBudget|budgetCap|usedPercent|预算参考|参考总预算|人均总额|BUDGET|MUST-GO` 在 `dist/` 中 0 匹配）。

### 2.5 Hero 与 TripSpine 响应式与场景 Label 展示
- Hero 头部预估胶囊添加 `xl:hidden`，仅在移动端呈现；桌面端依赖 `TripSpine` 呈现。
- Hero 胶囊与 `TripSpine` 均可展示当前激活场景 `label`（如 `"高铁往返方案"`）。

### 2.6 必去地点标记与地图地点详情 (Must-Include Places in Cards & Map Modal)
- **行程卡片与地图地点详情全覆盖**：
  - 景点卡片及地图/卡片点开的地点详情弹窗 (`PlaceDetailModal.tsx`) 中均正确渲染绿色 **`"你的必去"`** 徽标。
  - 严格依据 `item.status === "scheduled" && item.place_id === place.place_id` 进行匹配，禁绝任何基于名称的模糊匹配。
- **Hero 下方微型告示 (`MustIncludeNotice.tsx`)**：
  - 涵盖 `not_scheduled`, `cross_city`, `recorded_candidate`, `recorded_unmatched` 4 种非排入状态；当全部景点均已排入时隐去。
