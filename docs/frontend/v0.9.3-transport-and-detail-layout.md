## 2. 大交通推荐卡(本期核心交付)

### 2.1 数据契约(v0.9.3 后端已上线)

`GET /trip/results/{result_id}` → `plans[].transport`(可选,加性字段,`schema_version` 仍为 `"1.4"`)。

**读取规则(硬性):**
- 所有 plan 的 `transport` 是同一份数据 → **只读 `result.plans[0].transport`**,与当前查看的 planId 无关,在方案切换层之外渲染一次。
- `transport` 为 `null`(旧记录 / 同城 / flag 关闭)→ **完全不渲染**:无卡片、吸顶 Tab 无「交通」胶囊、无占位、不报错。

```ts
// src/types/trip.ts 新增
interface TransportOption {
  type: "train" | "flight";
  no: string;                    // "G3" | "MU5101"
  departure_time: string;        // "09:00"
  arrival_time: string;
  duration_minutes: number;
  price: string | null;          // 航班恒为 null,价格只看 mode 级
  departure_station: string;     // "北京南" | "PEK"
  arrival_station: string;
  airline: string | null;        // 仅航班有
}
interface TransportMode {
  mode: "train" | "flight";
  min_duration_minutes: number;
  price_range: string;           // 后端已格式化,原样展示,禁止二次解析
  price_source: "realtime" | "static_reference";
  daily_count: number;           // 0 时隐藏班次数
  data_source: "realtime" | "static_fallback";
  availability_status: "available_at_query" | "sold_out_at_query" | "unknown";
  availability_checked_at: string | null;  // ISO UTC
  options: TransportOption[];    // Top5,静态降级时为空数组
}
interface TripTransport {
  from_city: string;
  to_city: string;
  query_date: string | null;     // null = 无日期静态估算
  source: "realtime" | "mixed" | "static_fallback";
  modes: TransportMode[];
}
```

### 2.2 渲染形态

> 2026-08-02 后端确认(以下为**产品决策**,覆盖早前评审稿的"主卡+候补票根"设想):
> - `modes` 顺序恒为 train 在前、flight 在后(如有),是**固定结构序,不是推荐序**。
> - **双模式等权展示**,用户自己挑。不给任何一行做视觉降权/主次层级(Writer 正文同口径:「高铁约X小时,或飞机约Y小时」)。
> - **按每项的 `mode` 字段分发渲染,禁止按下标假设类型**。合法形态:`[train]`、`[train, flight]`、`[flight]`(远期日期且无静态火车数据时出现纯飞机)。
> - 双模式触发阈值为高铁 **>3 小时**(非 4 小时,仅口径备忘,前端无此逻辑)。
> - 未来若加推荐倾向,由后端加 `recommended` 字段;**前端不得自行按时长/价格定推荐**。

**统一形态:一张票卡,内含 1~2 行等权的 mode 摘要**

```
┌─────────────────────────────────────────┐
│  北京 ────────────→ 上海                 │  ← 地名 font-display 大字对排,
│                                         │     虚线连线(单模式时用该 mode 图标,
│ ─ ─ ─ ─ ─ ─ ✂ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─    │     双模式时不偏向任一方式)
│  🚄 高铁  最快 4h30m · ¥626-661 · 每日约52班 │  ← mode 摘要行(等权)
│     ▸ 车次参考(Top5,默认收起)            │
│  ✈  飞机  最快 2h50m · ¥800-1500(参考价)·每日约N班 │  ← 同级样式,无降权
│     ▸ 航班参考(默认收起)                 │
└─────────────────────────────────────────┘
```

- 每行图标/文案由该项的 `mode` 字段决定(`train`→🚄 高铁,`flight`→✈ 飞机),两行字号、字重、颜色完全一致。
- 单模式(`[train]` 或 `[flight]`)即只有一行摘要;`[flight]` 单独出现是合法形态,必须正确渲染。
- **禁止**:对等两列比价表(横向对比布局)、任一行的灰度/压扁/降权处理、前端自行标注"推荐"。

**Top5 options 列表(展开态)**,紧凑行式,非表格撑满:

```
G3    09:00 北京南 → 13:40 上海虹桥   4h40m   ¥626
G11   10:00 北京南 → 14:28 上海虹桥   4h28m   ¥626
```

- 火车行显示 option 级 `price`;航班行 `price === null` **不渲染价格列**(价格只在 mode 级 price_range 体现)。
- 航班行以 `airline + no` 开头:`东航 MU5101`。
- `options` 为空数组(静态降级)→ 不渲染该行的展开入口,只有摘要。

### 2.3 字段展示规则

| 字段 | 规则 |
|---|---|
| `price_range` | **原样展示**,后端已含"(参考价)""以购票平台为准"等后缀,前端不解析不拼接 |
| `price_source === "static_reference"` | price_range 旁加灰色小徽章「参考」(若文案已含"参考价"则不重复加) |
| `daily_count === 0` | 隐藏"每日约N班"整段 |
| `availability_status === "sold_out_at_query"` | 摘要行下加琥珀色提示条:`查询时段车票已售罄,请以购票平台实时余票为准` |
| `availability_status === "unknown"` | 不渲染任何余票信息 |
| `availability_checked_at` | 非 null 时在卡片底部灰色小字:`余票查询于 MM-DD HH:mm`(UTC→本地时区,`Intl.DateTimeFormat`) |
| `source === "static_fallback"` 或 `query_date === null` | 卡片底部灰色小字:`静态估算,班次与价格以购票平台为准` |
| `min_duration_minutes` | 格式化为 `N 小时 M 分`(M=0 时省略),与页面"驾车预计 33 分钟"文风一致 |
| 所有数字 | `tabular-nums`;数字与单位间用 `&nbsp;` 防断行 |

### 2.4 位置与导航

- 卡片位置:Hero 之后、第 1 天之前,`<section id="transport" className="scroll-mt-24">`。
- `transport` 非 null 时,吸顶 Tab 章节序列为 `[概览][交通][第N天…(移动端)][预算][必去]`。
- 新组件:`src/components/detail/TransportCard.tsx`。

## 3. 行程脊柱(PC ≥1280,无后端依赖,可与 §2 并行)

- 位置:正文左侧,`sticky`,`top` = 吸顶栏实际高度 + 间距;宽约 120-160px。
- 每节点仅三样:**日序号 + 天气图标 + 高温**(`01 ☀ 40°`),用现有 `font-display text-[11px] uppercase tracking-[0.2em]` 风格。天气图标用 Font Awesome 单色线性图标(`fa-sun`/`fa-cloud-rain` 等,`text-gray-400`,当前天 primary 色),**不用 emoji**(emoji 仅保留在正文内联标签)。
- 无天气数据的行程(`weather.days` 为空):脊柱仍渲染,节点只有日序号,不出天气图标。
- 进度语义:当前天节点放大高亮,已读节点实心,未读空心,节点间线段随滚动填充。
- 交互:节点为 `<a href="#day-N">`(支持 Cmd+click),当前天加 `aria-current="location"`;整栏包在 `<nav aria-label="每日行程导航">`。
- 联动:复用现有章节 scrollspy 的 IntersectionObserver,**不新挂 scroll 监听**。
- 聚合提醒:脊柱底部一条(`⚠ 第3天有雨`),来自 `weather.days[].reminders` 去重;提醒规则同时纳入极端高温(≥40°C)。
- 同时:吸顶 Tab 的逐日胶囊**全端保留**(2026-08-02 产品决策:Tab 永远吸顶可见,脊柱需滚动到位,双入口换便利可接受;推翻早前评审稿的"PC 删逐日胶囊")。
- 长行程:脊柱容器 `max-h-[calc(100vh-{top偏移})] overflow-y-auto overscroll-contain`,滚动条做通透样式。

## 4. 天气横带 + 聚合提醒(<1280px)

- 位置:Hero 之后、去程票卡之前(正文流段落,**不 sticky**)。
- 形态:一行 N 个小格(`周三 6/28 ☀ 40°/28°`),`overflow-x-auto` + `overscroll-behavior-x: contain`,7 天内通常无需滚动。
- 聚合提醒条挂在细带正下方,仅 `reminders` 非空时渲染;数据随首屏同步渲染(不异步插入,防 CLS)。
- `weather.status !== "ok"` 或 `days` 为空:整个模块不渲染(`skipped_date_out_of_range` 时可渲染一行灰字说明,其余状态一律隐藏)。
- 现有 `WeatherCard.tsx` 不动(经典对照页仍在用);新组件 `WeatherStrip.tsx`。

## 6. 工程红线(评审汇总,验收必查)

1. 所有跳转用 `<a href="#...">` 而非 div onClick;目标 section 已有 `scroll-mt-24` 的保持,新增的必须加。
2. sticky 元素(脊柱)上**禁止** transform 类 GSAP 动画(会破坏 sticky 定位);只允许一次性 opacity 淡入,且走 `prefers-reduced-motion` 分支。
3. DOM 顺序:正文在前、脊柱在后(grid `order` 调视觉位置),避免键盘 Tab 先穿越 7 个天气链接。
4. 票卡/天气细带的可点区 ≥44×44,整行可点。
5. 天气数据与内联标签同源(`result.weather`),脊柱/细带是纯派生 UI,零新增请求。
6. emoji 图标 `aria-hidden="true"`,语义由文本承载(如 `aria-label="第3天,雨,最高26度"`)。
7. 断点:三栏仅 `xl:`(1280) 起;1024-1280 与移动端同构,不做中间态。
