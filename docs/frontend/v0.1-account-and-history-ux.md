> Status (2026-08-01): **Core UX Implemented / Dynamic Quota Display Repair Pending**

## 1. 认证路由与受保护资源访问规范

### 1.1 独立 `/login` 路由与 `returnTo` 恢复机制
- **路由形态**: 独立 `/login` 页面（非 Modal 弹窗）。
- **受保护拦截与重定向**:
  - 未登录用户触发受限操作或访问受保护路由时，重定向至 `/login?returnTo=<encoded_path>`。
  - 登录成功后，自动重定向恢复至 `returnTo` 目标路径（默认重定向至 `/`）。
  - **安全约束**: `returnTo` 必须严格限制为同源相对路径（必须以 `/` 开头且不能以 `//` 开头），防止 Open Redirect 漏洞。

### 1.2 路由白名单与纵深防御 (Route Guards & Defense-in-Depth)
- **公开白名单路由**: 仅限 `/login` 与 `/`（首页产品展示/填表落地页）。
- **受保护路由**: `/planning/:jobId`（等待页）、`/result/:resultId`（结果页）、`/plan/:resultId/:planId`（详情页）、`/history`（我的行程）、`/profile`（个人设置）。
- **前端路由守卫**: 未登录游客敲 URL 直接进入受保护路由时，立即拦截并带 `returnTo` 重定向至 `/login`。
- **BFF 后端纵深防御**: BFF 在所有数据/操作接口 (`POST /api/trip/async`, `GET /api/trip/jobs/*`, `GET /api/trip/results/*`, `GET /api/me/trips`) 强校验 Session Cookie 与用户所有权，未登录/越权请求返回 `401 AUTH_REQUIRED` 或 `404 TRIP_NOT_FOUND`。

### 1.3 邮箱验证码流程与防枚举安全规范
- **模式切换**: `/login` 页面包含顶部 Tab：`[邮箱登录]`（默认）与 `[邀请码注册]`。
  - 登录模式字段: 邮箱地址 + 邮箱验证码。
  - 注册模式字段: 单次邀请码 + 邮箱地址 + 邮箱验证码（3 个字段缺一不可）。
- **发送验证码阶段防邮箱枚举 (`POST /api/auth/email/send-code`)**:
  - 无论邮箱在系统中是否存在，BFF 均统一返回相同的成功响应。
  - **发送阶段绝不返回** `USER_NOT_FOUND` 或 `EMAIL_ALREADY_REGISTERED`。
- **验证码成功校验后的 Tab 模式纠偏 (`POST /api/auth/email/verify`)**:
  - 只有在 OTP 验证码成功校验通过后，BFF 才进行账号状态判断：
    - 若以 `login` 模式验证了一个尚未注册的邮箱，BFF 返回 `409 REGISTRATION_REQUIRED`，前端自动切换至 `[邀请码注册]` Tab，保留邮箱，高亮邀请码框提示：“该邮箱尚未注册，请输入邀请码完成注册”。
    - 若以 `register` 模式验证了一个已注册的邮箱，BFF 返回 `409 LOGIN_REQUIRED`，前端自动切换至 `[邮箱登录]` Tab，保留邮箱，提示：“该邮箱已注册，已自动切至登录模式”。
  - **原则**: 模式纠偏发生在 OTP 校验之后，纠偏过程绝不提前创建用户、Session、额度或消耗邀请码。

### 1.4 表单交互与原地错误恢复
- **单页集成表单 (Single-Card Form)**: 不采用 Step 1 ➔ Step 2 分步向导。
- **验证码 60s 倒计时**: 验证码发送成功后，按钮开启 `60s` 内联倒计时。
- **原地错误恢复**:
  - 邀请码无效/已用完 (`INVITATION_INVALID` / `INVITATION_EXHAUSTED`): 在邀请码框下方展示红字内联错误，不清空已填邮箱，用户直接在原地修改邀请码。
  - 频率受限/邮箱非法 (`RATE_LIMITED` / `INVALID_EMAIL`): 按钮不开启倒计时，内联展示错误。
  - 验证码错误/过期 (`OTP_INVALID` / `OTP_EXPIRED`): 自动清空验证码框并获得焦点，保留邮箱与邀请码。

### 1.5 Header 状态与全站统一视觉语言
- **全站视觉系统**: 严格复用全站统一设计系统（主色松石绿 `primary-500` `#0f766e` + 强调橙 `accent-500` `#f97316` + 暖砂背景 `bg-sand-50`/`bg-white/80` 毛玻璃）。
- **游客态**:
  - 桌面端展示高亮按钮 `[ 登录 / 注册 ]` (`bg-accent-500`)；移动端展示 `[ 登录 ]` 文本/按钮。
- **登录态**:
  - **额度胶囊**: 显示 `⚡ 额度 remaining/limit`（正常 `bg-primary-50 text-primary-700`，耗尽 `bg-amber-50 text-amber-700`）。两个数值都读取 BFF `GET /api/me`，不得硬编码 `/3`。悬停提示：“公测期免费额度：成功生成扣减 1 次，失败/超时自动退还”。
  - **我的行程入口**: 桌面端展示 `[ 我的行程 ]` 文本链接。
  - **用户菜单与移动端 Drawer**: 点击脱敏邮箱（如 `u***@example.com`）展开下拉菜单，包含 `[ 个人设置 ]` (`/profile`)、`[ 我的行程 ]` (`/history`) 与 `[ 退出登录 ]`。

### 1.6 未登录提交暂存与额度预占 (RESERVED) 控制
- **未登录提交拦截与暂存**:
  - 未登录游客在首页填表点击“帮我排行程”，前端拦截请求，将 `formData` 序列化暂存至 `sessionStorage`，带 `returnTo=/` 跳转至 `/login`。
  - 登录成功重定向回首页，初始化检测到暂存数据后，回填表单、自动发起 `submitTrip(formData)` 并进入等待页。若额度为 0，则优雅拦截并提示。
- **额度预占中 (RESERVED) 全局封锁**:
  - 当后台有任务处于 `PENDING` / `RUNNING` 时，Header 显示 `⚡ 额度 remaining/limit (规划中...)` 并伴有 Spinner 旋转。
  - 首页提交按钮置灰禁用 (`disabled`)，显示 `正在规划中...`，全站禁止并发重复提交。

### 1.7 失败超时额度退还与重试 (Quota Settlement & Retry UX)
- **额度退还印证**:
  - 任务在等待页陷入 `FAILED` / `TIMEOUT` / `REJECTED` 时，BFF 保证事务性退还预占额度（RELEASED）。
  - 等待页醒目标注印证徽章：`✓ 本次失败未扣除额度（已自动退还）`，Header 额度实时复原。
- **恢复路径双按钮**:
  - **`[ 再试一次 ]` (高亮橙色主按钮)**: 读取保存的同份参数，直接重新发起 `submitTrip(formData)`，生成新 `job_id` 并原地重启等待页。
  - **`[ 调整偏好 / 重新规划 ]` (白底次要按钮)**: 携带原参数回填并跳转至首页 `/`。

### 1.8 七天历史行程列表页 (`/history`) 规范
- **7 天归档提示**: 页头标注 `ⓘ 提示：行程记录生成后将在 7 天内保留展示，超时后自动归档`；每张卡片标注归档倒计时。
- **成功卡片 (`SUCCESS`)**: 展示城市、天数、生成时间、`✓ 已生成` 徽章、`[ 查看路书 ]` 按钮。
- **失败卡片 (`FAILED` / `TIMEOUT` / `REJECTED`)**: 展示城市、天数、生成时间、`✕ 未完成` 徽章、`✓ 额度已退还` 印证标签、`[ 用原参数重试 ]` 按钮（使用 BFF 返回的 `retry_input.trip_request` 重试）。
- **重试契约与隐私**: 重试时仅使用 `retry_input.trip_request`，绝不恢复 `source`、`conversation_id`、内部 Prompt 或逻辑字段；`notes` 仅在 7 天保留期向本人展示，注销后擦除。
- **无单条删除说明**: 卡片上不提供单条删除按钮。页脚说明：“v0.1 不提供单条行程删除。账号注销会删除登录身份和会话，并解除历史行程与账号的关联；去标识化的行程内容和质量数据将继续保留。”

### 1.9 会话生命周期与多标签页广播同步 (Session & Broadcast)
- **7 天绝对过期**: 响应 BFF 7 天绝对到期规则，全局 401 拦截器捕获 `401 AUTH_REQUIRED` / `SESSION_EXPIRED` 后弹 Toast 提示，清除本地状态并带 `returnTo` 跳转 `/login`。
- **主动退出登录**: 点击“退出登录”调用 `POST /api/auth/logout`，清空状态并刷新至首页游客态。
- **多标签页广播 (`BroadcastChannel`)**: 挂载 `yuntu_auth_channel`，Tab A 状态变化时广播 `AUTH_STATE_CHANGE`，Tab B 实时同步 Header 与受保护路由状态。

### 1.10 PDF 导出鉴权与所有权 (PDF Export & Ownership UX)
- **所有权校验**: 游客点击弹 Toast“请先登录后导出 PDF”并引导跳转；越权导出他人 PDF 时 BFF 返回 `404 TRIP_NOT_FOUND`，前端弹 Toast 警示并禁用按钮。
- **生命周期**: 复用 `useArtifact.ts` 响应生成中（按钮禁用）、成功（静默触发 Blob 下载）与失败（弹错恢复可重试）状态。

### 1.11 账号注销规范 (Account Closure UX)
- **入口**: 位于独立 `/profile` 个人设置页的危险区。
- **风险提示 Modal**: 展示不可逆风险警告：“v0.1 不提供单条行程删除。账号注销会删除登录身份和会话，并解除历史行程与账号的关联；去标识化的行程内容和质量数据将继续保留。”
- **二次验证码**: 必须输入通过 `POST /api/me/closure/send-code` 获取的 6 位验证码后方可点击确认。
- **409 活动任务阻断**: 若有未完成任务（`SUBMITTING` / `PENDING` / `RUNNING`），BFF 返回 `409 ACTIVE_TRIP_IN_PROGRESS`，前端阻断注销并提示等待任务结束。
- **注销完成**: 调用 `POST /api/me/closure/confirm` 成功后，广播 `LOGOUT` 事件并强切至 `/login`。

## 2. 决策记录 (Accepted Decisions)

| # | 拷打主题 | 冻结决策 | 核心理由 |
|---|---|---|---|
| 1 | 登录形态 | 独立 `/login` 页面，支持安全 `returnTo` | 适合邮箱多步验证码与 v0.2 OAuth Callback 流程，避免弹窗在重定向/刷新时丢失上下文。 |
| 2 | 注册/登录区分 | Tab 显式切换 (`[邮箱登录]` / `[邀请码注册]`) + OTP 后纠偏 | 满足 BFF 防邮箱枚举安全约定，只有在 OTP 成功校验后才触发 409 模式纠偏，不提前创号耗码。 |
| 3 | 表单交互 | 单页集成表单 + 60s 内联倒计时 + 原地错误恢复 | 行业最主流解法（如 Vercel/GitHub/掘金），路径最短、修改零阻力，无多余 Step 动画开销。 |
| 4 | Header 状态 | 额度胶囊 + 统一视觉语言 (`primary/accent`) + 移动端抽屉 | 保持全站松石绿/强调橙/暖砂白设计语言高度一致；额度外显增强预期；移动端简洁避让。 |
| 5 | 安全与未登录提交 | 路由白名单 + 纵深防御 (BFF强鉴权) + 暂存自动续接 | 仅 `/` 与 `/login` 开放白名单，等待/结果/详情页强拦截；BFF强校验防黑客越权；填表拦截后暂存自动续接提升体验。 |
| 6 | 额度与预占控制 | 服务端动态额度胶囊 + 预占双重封锁 + 额度耗尽禁用 | 预占锁定防重复提交并发；当 `remaining == 0` 时封锁提交并清晰提示，不假定固定额度上限。 |
| 7 | 失败退还与重试 | 额度退还印证徽章 + Header实时复原 + 同参原地重试 | 明确退还提示消除白白扣额度焦虑；同参原地重试大幅降低偶发超时后的重试摩擦。 |
| 8 | 七天历史列表 | `/history` 卡片流 + 7天归档倒计时 + `retry_input` 重试 | 对齐 BFF 契约 7 天 Retention；使用 `retry_input.trip_request` 原参重试；明确注销去标识化保留说明。 |
| 9 | 会话与多标签页 | 全局 401 拦截器 + BroadcastChannel 多标签页状态同步 | 响应 7 天绝对过期；防多标签页状态错乱；状态变更瞬时无缝同步。 |
| 10 | PDF 导出鉴权 | 所有权校验 + 未登录拦截 + useArtifact 状态继承 | 严防越权导出他人 PDF；响应生成中/成功/失败状态；复用已有 PDF 导出逻辑。 |
| 11 | 账号注销 | 独立 `/profile` 路径 + 409 阻断 + 去标识化保留提示 | 修正注销文案，明确擦除身份/解绑行程，保留去标识化内容；响应 409 活动任务阻断。 |
